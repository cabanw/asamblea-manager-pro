# Cambios v2.0 — resumen para debugging

Sesión de cambios previos al evento en vivo. Todo está en `main` y desplegado (Firebase Hosting + Supabase Edge Functions + DB). Este doc es contexto para debuggear fallas encontradas en pruebas.

## 1. Votación apagada (sin borrar)

**Por qué:** el evento en vivo no usa el módulo de votación/elecciones. Se apaga sin borrar código para poder prender en v2.1.

**Cómo funciona:**
- Flag central: `src/lib/featureFlags.ts` → `VOTING_ENABLED = false`
- `src/components/Header.tsx`: botones "Portal de Votos" y "Elecciones" (admin) ocultos si `VOTING_ENABLED` es false. **Las rutas siguen existiendo** (`/elections`, `/admin/elections`, etc.) — accesibles por URL directa, decisión tomada a propósito.
- `src/components/RegisterMember.tsx` (registro manual por staff): no genera PIN de votante ni muestra el diálogo "¡Registro Exitoso!" con PIN cuando `VOTING_ENABLED` es false. Toast simple de confirmación en su lugar.
- `supabase/functions/register-attendance/index.ts` (registro público por QR): misma lógica, constante local `VOTING_ENABLED = false` (no puede importar `src/lib`, es Deno aparte). No genera PIN, no manda SMS.
- `src/pages/RegistrationSuccess.tsx`: **sin cambios de código** — la tarjeta de PIN ya estaba condicionada a `state.voter_pin`, que ahora simplemente no llega.

**Qué debería verse:** ni staff ni asistentes ven PIN en ningún lado. Nadie recibe SMS de PIN. Los tabs de votación no aparecen en el menú para nadie (ni admin).

## 2. Botón "Mark Left" eliminado

**Por qué:** check-in es de una sola dirección para este evento — no hace falta desmarcar presencia.

**Cómo funciona:** `src/components/AttendanceManager.tsx` — se sacó `togglePresence` y el botón. Solo queda el badge Present/Left (display, sin acción). Nada puede volver a "Left" desde la UI una vez registrado.

## 3. Fix: registro por QR — dropdown de credencial vacío

**Causa raíz:** RLS de la tabla `positions` estaba restringida a `authenticated` (`auth.uid() IS NOT NULL`). El formulario público (`src/pages/PublicRegistration.tsx`, abierto sin login desde el QR) corre con anon key — la consulta devolvía 0 filas sin error, dropdown en blanco.

**Fix:** migración `supabase/migrations/20260801000001_allow_public_read_positions.sql` — política nueva `"Public can read positions"` con `USING (true)`. Solo afecta SELECT; insert/update/delete de posiciones siguen admin-only.

**Aplicado en producción** vía Supabase MCP (`apply_migration`), no vía `supabase db push` — ver sección 6.

## 4. Fix: registro de miembro nuevo por QR fallaba (500)

**Causa raíz:** trigger `after_members_change` en tabla `members` (dispara AFTER INSERT/UPDATE/DELETE) corre:
```sql
UPDATE public.assembly_sessions
SET total_active_members = (SELECT COUNT(*) FROM public.members WHERE is_active = true);
```
Sin `WHERE`. Este proyecto tiene el guard `safeupdate` activo, que rechaza cualquier UPDATE sin WHERE — error real en logs: `"UPDATE requires a WHERE clause"`. Abortaba toda la transacción de insert.

**Por qué solo fallaba con miembro nuevo:** invitados no tocan `members` (no dispara trigger). Miembros que ya existían solo hacen checkin (no insert en `members`, no dispara trigger). Solo miembro **nuevo** dispara el insert → trigger → error.

**Fix:** migración `supabase/migrations/20260801000002_fix_safeupdate_total_active_members_trigger.sql` — mismo UPDATE, agregado `WHERE true` (mismo comportamiento, satisface el guard).

**Aplicado en producción** vía Supabase MCP, verificado con insert de prueba (rollback, no dejó basura).

## 5. Quórum: 66.67% fijo en todos lados

**Causa raíz:** `src/pages/Register.tsx` calculaba quórum con `assembly_sessions.quorum_required` (columna configurable, default 50%), mientras `Index.tsx`, `Attendance.tsx` y `MetricsDashboard.tsx` ya usaban 2/3 fijo. Misma asamblea podía mostrar "quórum alcanzado" en un tab y "sin quórum" en otro.

**Fix:**
- Constante centralizada: `src/lib/quorum.ts` → `QUORUM_FRACTION = 2 / 3` (fijo por reglamento, no configurable).
- `Index.tsx`, `Attendance.tsx`, `MetricsDashboard.tsx`, `Register.tsx` — todos importan de ahí, ya no hay `2/3` hardcodeado suelto ni columna `quorum_required` en el cálculo.
- `src/components/SessionManager.tsx`: el diálogo "New Assembly" **ya no tiene input de % de quórum**. Muestra en su lugar el conteo en vivo de miembros activos y el umbral de quórum resultante (`Math.ceil(2/3 * activos)`).
- Tabla de sesiones: columna "Quorum" reemplazada por "Miembros Activos", mostrando `total_active_members` (snapshot tomado automáticamente al crear la sesión por el trigger `before_insert_assembly_sessions`, ya existía, ahora se usa).

**Cómo debería verse:** el card "Estado del Quórum" debe mostrar el mismo estado (alcanzado/no alcanzado) sin importar en qué tab estés (Inicio, Asistencia, Registro), siempre basado en 2/3 de miembros activos actuales. `Index.tsx` no tiene realtime (hay que refrescar); `Attendance.tsx` sí tiene realtime (se actualiza solo).

## Pendiente — no resuelto, anotado para después

**Historial de migraciones del CLI desincronizado del remoto.** `supabase db push` falla: el remoto tiene 2 migraciones trackeadas (`20260605221254`, `20260605222335`, aplicadas alguna vez vía MCP) que no matchean ningún archivo local por timestamp, y ninguna de las ~20 migraciones locales aparece registrada en el remoto tampoco — aun cuando el schema real sí las tiene aplicadas. Conclusión: la mayoría del schema se aplicó por fuera del flujo normal del CLI (dashboard/MCP) en algún punto, y la tabla de tracking (`supabase_migrations.schema_migrations`) nunca quedó consistente.

**Por eso**, los fixes #3 y #4 de este documento se aplicaron directo con `apply_migration` (Supabase MCP) en vez de `supabase db push` — es la única vía que sí quedó registrada correctamente hasta ahora. Los archivos `.sql` igual quedaron en el repo (`supabase/migrations/`) para que el historial de código sea completo, pero **no confíes en `supabase migration list` / `db push` para saber qué está aplicado en producción** hasta que esto se sanee con calma (no es urgente para el evento, pero sí antes de seguir acumulando migraciones).
